# 📄 Documentation Request Intake Template

To create clear and useful documentation, I need the following information before I can begin. This helps ensure we're solving the right problem for the right audience—without guesswork.

---

## ✅ 1. Who is this for?

- What team, role, or user type will use this documentation?
- What do they already know about the topic?
- What terms or tools are familiar to them?

---

## ✅ 2. What’s the goal?

- What task, decision, or process does this documentation support?
- Why does it need to be documented now?
- What’s the impact if it's not documented?

---

## ✅ 3. What does success look like?

- How will you know the documentation is working?
- What should users be able to do after using it?
- What mistakes or questions should this prevent?

---

## ✅ 4. What are the key topics or tasks?

- List the main topics, features, or tasks to be covered.
- Group related tasks or processes where possible.

_Example:_
- Logging in
- Resetting a password
- Submitting a support request

---

## ✅ 5. What details do you already have?

_Optional but helpful:_

- Known steps or rules
- Screenshots or links
- Common issues or “gotchas”
- Subject matter experts (SMEs) I can talk to

---

## ⚠️ Reminder

Saying “I need documentation” is a great start—but not the finish line. This intake helps us get it right the first time, faster.
